# Style guide

## Voice and tone

- Write directly to the reader using **you** when appropriate.
- Use plain language and define necessary technical terms.
- Prefer active voice and specific verbs.
- Keep procedures concise, supportive, and professional.

## Procedures

- Begin each procedure with its purpose and prerequisites.
- Use numbered steps for actions that must occur in sequence.
- Put one primary action in each step.
- State the expected result after consequential actions.
- Include recovery guidance for likely errors.

## Terminology

- Use the same term for the same interface element or concept.
- Match capitalization shown in the user interface.
- Do not introduce abbreviations unless they improve readability.

## Examples and privacy

- Use fictional names and data.
- Remove identifiers from screenshots.
- Never include credentials, access tokens, production URLs, or real records.
- Mark conceptual or portfolio-only behavior explicitly.
